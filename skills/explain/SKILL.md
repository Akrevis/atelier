# 分层讲解

先给浅的，让用户决定往下走多深。**一次讲完是本 skill 唯一的致命失败。**

## 第一层：默认给这四块

总长控制在 250 字内。顺序固定，缺哪块跳过哪块，不调换。

```
**一句话**：<这东西是什么、解决什么问题，1~2 句>

<图——能画就画，判据见下；画不了就没有这块>

**打个比方**：<一个类比，优先取材自用户在对话里展现过的技术背景>

**往下看哪个**：
1. <具体问题>
2. <具体问题>
3. <具体问题>
```

**一句话在图之前**，因为图需要定位才看得懂；但一句话必须短到不构成负担。除此之外图优先于文字。

### 追问菜单怎么列

2~3 条，每条必须是**一个具体问题**，不是一个主题范围。

- 好：「为什么挥手要四次而握手只要三次」「什么情况下它会比另一个方案慢」
- 坏：「TCP 的更多细节」「进阶用法」——这种等于没给

菜单的价值在于**列出用户自己想不到、但确实该知道的东西**。用户不知道自己不知道什么，所以问不出关键问题——这几条就是替他把问题问出来。

用户回复编号或说出方向后，**只讲那一条**，讲完继续给新菜单。

## 往下深入时讲什么

进入第二层及以下，按这个顺序展开（不必每层都走完五步，用哪步取决于用户点的方向）：

1. **背景痛点** — 这东西出现之前，人们面临什么问题、旧方案为什么不够。让概念以「问题的答案」身份登场，而不是孤立名词
2. **设计取舍** — 在什么约束下、做了什么取舍、代价是什么。这一步让概念可推理而非死记
3. **串联体系** — 接到用户已知的和将学的之间，形成网络
4. **边界** — 什么情况下它失效、不该用它、换别的方案更好
5. **可迁移框架** — 提炼一个下次能复用的判断工具

**隐喻是拐杖不是理解本身**：用了比方之后，最终要能脱开比方、用机制本身说清。

## 画图

### 判据

**能说出「有哪几个东西、它们之间是什么关系」就画。**

| 能画 | 不画 |
|---|---|
| 流程 / 顺序 | 纯定义（「X 是一种 Y」） |
| 结构 / 层次 | 单一事实（版本号、参数值） |
| 状态变迁 | 论述性的理由与取舍 |
| 调用 / 依赖关系 | |
| 两个方案的对比 | |

论述性内容画成图会失真——它本来就是线性的因果链，硬塞进方框里只会丢掉逻辑连接词。

### 规格

用闭合框，`┌ ─ ┐ │ └ ┘ ├ ┤ ▼ ►`。

- **整图宽度 ≤ 60 列**
- **逐字符核对宽度**：中文和全角标点占 2 列，ASCII 占 1 列。算错一个字，右框线就崩
- **箭头等宽度不定的符号不放进框内**，只用于框外连线
- **注解贴在图元素上**（箭头旁、框内、节点边），不允许图画完之后另起一段文字复述这张图

### 节点多了怎么办

| 节点数 | 处置 |
|---|---|
| ≤ 8 | 直接画 |
| 9~15 | **拆成两张分层图，或只画主干省略细节节点**——不要硬塞进一张 |
| > 15 | 画主干，并告诉用户 `/palette` 能出完整的可视化版本 |

## 要一轮复述的时机

**两个条件同时满足才要，一次会话最多要一次：**

1. 这一轮讲的内容有取舍、会影响用户后续的决策（不是纯事实陈述）
2. 用户既没有追问、也没说出自己的理解，只回了「懂了」「好的」「明白」

其余情况一律不要——用户在追问，本身就证明他在思考。

### 判过关的标准

> **照他说的这套去做决策不会做错，就算过。**

| 算核心，错了要纠 | 算细节，错了不打回 |
|---|---|
| 解决什么问题 | 具体参数值、函数名 |
| 大致怎么解决 | 步骤的精确顺序 |
| 关键取舍与代价 | 用词是否专业 |

用户说「它会把数据存起来」，不要纠正成「应该说持久化」。意思对就过，顶多顺带提一句正式说法，**不重讲、不要求复述第二遍**。

用户不想复述就不复述，提一次即可，不纠缠。

## 标记

只在下列三种情况用，其余场合不用——它们是内容类型的标签，不是装饰：

- ⚠️ 坑：会踩、会出事的地方
- 💡 关键洞察：这一段的核心，漏了就白讲
- ❌ 反模式：常见的错误做法

## 反面模式

- **一次把五层讲完**。用户表现出的「枯燥」多数是过载，不是不感兴趣——一次倒完直接触发放弃
- **追问菜单写成笼统主题**。「更多细节」「进阶内容」不给用户任何可选择的东西，等于没有菜单
- **图画完又用文字复述一遍**。图和它的复述只能留一个，留图
- 对纯约定、原始事实硬套「背景痛点」和「设计取舍」——会**虚构出不存在的历史动机**，比不解释更糟
- 因为用词不够专业就打回复述
- 讲完不给菜单，停在那里等用户自己想问题
