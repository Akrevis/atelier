# atelier · 设计文档

> **两个产物，刻意解耦**：`owncc.md`（output style，已在用）· `atelier`（Claude Code 插件，开发中）
>
> 本文只记**已拍板**的设计。理由与被否决的方案在 `devlog.md`，未解决的缺陷与待办在 `backlog.md`。

---

## 一、定位

> **让 AI 的输出可学——从「给你结果」变成「给你理解」。**

**责任边界**：AI 负责讲清楚；**用户的理解能力不是 AI 要管的变量**。主导权在用户——用户刨根问底，AI 再讲。AI 不做验收官姿态，不主动出题。

---

## 二、为什么存在

拿 AI 学习，相比「看书 + 自己练」：

**得到**：零成本无限追问 · 按背景定制类比 · 即时答案

**失去**：

| 丢的 | 表现 |
|---|---|
| 大纲 | AI 是响应式的，只答你问的。你问的范围 = 你知道自己不知道的范围 |
| 图 | 默认吐线性文字，结构性知识失真 |
| 难度梯度 | 对新手和专家可能给同一段话 |
| **挣扎** | 成本为零的捷径人一定会走，而挣扎正是记忆编码的必要环节 |

**AI 独有的新伤害**：**它能替你做**。书不能。于是产出物出来了、能力没长，而且你以为长了。

**实证依据**：Anthropic 研究（52 名初级工程师学 Trio 库）——用 AI 组测验 50%，手写组 67%。更精确的一刀：**用 AI 做概念性提问的人 65%+，让 AI 代写代码的人不到 40%**。

---

## 三、两个产物

按**维度**切，不按功能切——这样两边不重复，各自也能单独使用：

| 产物 | 形态 | 管什么 |
|---|---|---|
| **owncc.md** | output style，单文件 | **怎么说**——渲染前置 · 分层结构 · 画图规格 · 颜文字 · 语言 · 沟通风格 |
| **atelier** | Claude Code 插件 | **做什么**——讲解流程 · 卡壳分档 · 画板命令 · 沉浸模式 |

单独装 owncc：输出格式变好，但没有讲解流程。单独装 atelier：流程完整，格式靠模型自由发挥。组合才完整。

**为什么 owncc 不收进插件**——技术上可以（插件支持 `output-styles/` 目录和 `outputStyles` 清单字段），但会毁掉三件事：

1. **独立性**：想要格式规范就必须连整个插件一起装
2. **全局唯一的 style 位被占**：装了 atelier 就不能再用 Concise 或任何别的 style
3. **`force-for-plugin` 会覆盖用户自己的设置**，多个插件都设时只有第一个加载的生效，且是静默失败

**安全底线绝不进 output style**：它可被 `/config` 随时切换，搬进去等于给底线装了个开关——与「进了包，卸载那一刻底线就消失」是同一个陷阱。

## 四、日常模式（MVP 范围）

### 组件

| 组件 | 类型 | 触发 |
|---|---|---|
| `explain` | skill | 用户问概念 / 原理 / 为什么这么设计 |
| `code-walkthrough` | skill | AI 要写非平凡代码时 |
| `/palette` | command | 用户主动敲，`disable-model-invocation: true` 从机制上保证 AI 不能自己调 |

**画板不做独立 skill**——它没有独立触发时机，是「讲解时顺带画」。画图规格整块归 `owncc.md`，skill 只负责在流程里决定这一步要不要出图。

**`references/` 只放按需查阅的材料**：官方加载机制是它需要 AI 主动读取、不自动进上下文。每次都要遵守的规则必须写进 `SKILL.md` 正文或 `owncc.md`。单个 `SKILL.md` 控制在 500 行以内。

**eli5 被吸收，不并存**：深度是分层协商出来的，eli5 与深度讲解的唯一区别（深度）就不成立。eli5 的价值（精简、通俗、追问菜单）成为 `explain` 的第一层默认形态。

### 讲解流程

痛点开场 → 隐喻锚定 → 设计取舍 → 串联体系 → 可迁移框架。

1. **分段交付**：讲 1~2 步就停，不一次讲完
2. **分层交付**：默认从最浅开始，每层结尾给追问菜单，用户往下点。深度是协商出来的，不是 AI 预判的
3. **追问菜单双向**：既列「往下学什么」，也列「AI 需要问用户什么」。用户选不选、选了几次，成为判断「要不要进深度讲解」的信号
4. **不启用深度讲法的情况**：纯约定 / 原始事实 / 纯形式定义 / 审美判断——强行套「背景痛点」会虚构不存在的历史动机

### 复述验收

> **判据：照他说的这套去做决策不会做错，就算过。**

| 算核心，错了要纠 | 算细节，错了不打回 |
|---|---|
| 解决什么问题 | 具体参数值、函数名 |
| 大致怎么解决 | 步骤的精确顺序 |
| 关键取舍与代价 | 用词是否专业 |

**反模式**：不许因为用词不精确就打回。说「把数据存起来」不该纠正成「持久化」。意思对就过，**不重讲、不要求复述第二遍**。

### 写码前讲思路

写码前先讲实现 / 数据流 / 边界，讲完停。TDD 可配置（TDD / 写完再测 / 混合 / 不测）。数据流日志不怕冗余，收尾问要不要清理。

**git 存档不进包**——它是全局 CLAUDE.md 的无条件底线，进包卸载即失效。

### 卡壳解锁（三档）

理论依据：**样例效应**（对新手，给完整样例 + 讲解比让他摸索更有效）＋**专长逆转效应**（对新手有效的支架对熟手是累赘，反之亦然）。

| 状态 | 判据 | 给什么 |
|---|---|---|
| 真不会 | 说不出「这东西大概要干什么」 | 完整样例 + 数据流讲解 |
| 卡细节 | 说得出思路，写不出来 | 提示 / 伪代码骨架，不给完整实现 |
| 懒得想 | 明显能说清但直接要代码 | 骨架 + 失败测试 + 试过的两个方向 |

**判断方式（零摩擦）**：默认直接给样例，不问。只有前面对话里已经看得出用户说清了思路，才降级到第二档——判断依据是看前面对话，不是反问一句。

**唯一硬要求**：样例给完之后，**关掉它自己重写一遍**。worked example 后面必须跟独立练习。

## 五、画板

| 环节 | 机制 |
|---|---|
| 默认呈现 | ASCII，按「能画就画」自动出，零注意力断点 |
| 撑不住时 | AI 建议、不自动生成；用户敲 `/palette` |
| 存储 | 单文件 `~/.claude/atelier/palette.html`，**不分全局/项目** |
| 复看 | 同会话内多图做成 tab 切换 |
| 生命周期 | 会话内累积 → 新会话第一次 `/palette` 全部重置 |

**完整画图规格在 `owncc.md`**——分流判据（表格 vs 框图 vs 纯文字）、框内只放 ASCII、87 列上限、节点数处置。本文不重复。

**裸 Mermaid 直接毙**：终端不渲染，用户看到的是源码，比纯文字更难读。

**「我想留下这张图」是另一个需求**，已分离成 T-12，第二版单独设计。两个需求混在一个文件里，通常两边都做不好。

## 六、沉浸模式（第二版）

| 阶段 | 动作 | 产出 |
|---|---|---|
| 立项 | 说需求 → 分析目标/标准 → 摸底测水平 → 联网搜真实资料 → 问可用时间 | 学习计划文档 |
| 执行 | 分阶段推进 / 卡壳三档 / 测试策略可配置 | 代码、练习 |
| 验收 | 分阶段考核 | 错题本 |
| 复盘 | 按到期重考旧知识点 | 复习记录 |

### 已定

1. **大纲必须有锚**：可以做大纲，但必须锚在外部可验证材料上（JD、官方文档目录、标准、真实课程结构），不许凭训练记忆直吐
2. **时间预算诚实化**：第一次立项没有依据，只能粗估并明确标注「通用经验估计，误差可能很大」；第二阶段起用实际耗时校准
3. **复习调度用 SM-2 式反馈控制，不画曲线**：每个知识点独立跟踪，答对 → 间隔 × 系数，答错 → 重置。艾宾浩斯只用来给初始间隔一个起点
4. **状态存项目目录的文件里**，不用 memkeep（语义不匹配 ＋ 包不得依赖包）
5. **不激活时完全静默**：不加载、不注入、不提示、不问「要不要开启学习模式」

### 学习方法落地性

| 方法 | 落地性 |
|---|---|
| 费曼 | 已有——复述闭环就是费曼 |
| 康奈尔笔记 | 可做笔记模板，与「纯 Markdown」偏好兼容 |
| SQ3R | 部分——它是读材料的方法，可迁移的是「先提问再学」和「主动回忆」 |
| 西蒙 | 只留「目标拆分」 |
| 番茄 | 不做——AI 无法计时、无法主动打断 |

> **西蒙学习法的事实纠正**：「6 个月精通任意领域」不是 Herbert Simon 的观点，是中文互联网的营销化改写。Simon 的实际结论相反——专业能力约需 10 年 / 数万小时（「一万小时定律」的源头）。这个假承诺会毒化时间预算模块。

---

## 七、硬约束

1. **装上就用，卸载就干净**——不要求用户改 CLAUDE.md 或 settings.json
2. **不得依赖任何其他包**
3. **每个分支、每条检查、每个规则必须能说出真实触发场景**——说不出就删
4. **不阻断 ≠ 不告知**——静默失败必须有同路径、同触发时机的自检
5. **沉浸模式不激活时完全静默**

---

## 八、竞品与差异化

| 竞品 | 重合处 | atelier 多什么 |
|---|---|---|
| 官方 Learning output style | 写码时停下让你实现一小段、插 `TODO(human)` | 画板 · 沉浸模式 · 卡壳分档 |
| rodbv/socratic-skills | 逐题验收、读 diff 检查、不给代码 | 卡壳三档 · 项目级作用域 · 复习调度 · 画板 |
| Anki / SuperMemo | 间隔重复 | **自动把错题变成复习项**（Anki 要手动制卡） |

自己实现，不依赖外部包。但吸收 `quiz-me` 的具体机制：出题判据（「不能靠复制粘贴源文件一行字回答」）、题型库、追问句式（「你说了 X——那 Y 边界情况呢」）、模糊回答检测（说「更高效」要追问具体）。
