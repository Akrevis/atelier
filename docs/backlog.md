## P0

### D-02 · palette 的「会话清空」与「分全局/项目」互斥 🔴

**问题**：两条已定规则逻辑上冲突——

- 按会话清空 → palette 是**临时**的
- 分全局/项目存 → palette 是**持久且有归属**的

既然每次会话都清空，分全局/项目就没意义，反正活不过这次会话。

**建议解法（待确认）**：palette 降级为**当次会话的临时画板**，生成在当前工作目录，不分全局/项目。持久化知识地图是另一个需求，现在不做。

## P1

### D-03 · 中等复杂度的图掉进缝里 🔴

**问题**：复杂度路由有个断层——

| 节点数 | 现有规则 | 结果 |
|---|---|---|
| ≤8 | ASCII | ✅ |
| **9~15** | ASCII 画不下；`/palette` 又必须用户主动敲 | ❌ **AI 只能说「建议敲 /palette」然后用文字讲**——「能画就画」落空 |
| 更复杂 | 用户敲 `/palette` | ✅ |

**建议解法（待确认）**：中间地带**拆图或画主干**——15 节点拆成两张 8 节点的分层图，或只画主干省略细节节点。符合分层交付的精神，但规则里没写。

### D-04 · 复述验收的触发时机没定死 🔴

**问题**：现有表述是「用户没在追问、或只说懂了 → AI **可以**要一轮复述」。「可以」不是可执行的条件。

**影响**：每次讲完都要 → 烦；从不要 → 形同虚设。不定死则实际行为随机。

**建议解法**：无。**需要一条明确的触发条件**，待设计。

---

### D-05 · explain 与 code-walkthrough 边界重叠 🔴

**问题**：真实场景会同时命中两个 skill——

- 「帮我实现一个 LRU 缓存」→ 要写代码（code-walkthrough），但 LRU 本身要讲（explain）
- 「这段代码怎么工作的」→ 不写新代码，但也不是纯概念

**建议解法（待确认）**：**有代码产出 → code-walkthrough**（内部沿用 explain 的讲解规范）；**无代码产出 → explain**。

## 已解决

### D-07 · ASCII 形态选型与宽度上限 🟢

**测试**：同一内容（HTTP 请求链路）出两种形态——闭合框 vs 不闭合树形。

**结论：用闭合框（形态 A）。**

我原本推断不闭合形态更稳（右边参差不影响结构），用户实测判定闭合框读起来更好，推断被否。

**关于对齐的两个失败点，要分开看**：

| 失败点 | 归属 | 处置 |
|---|---|---|
| 窗口太窄导致折行 | 环境，不可控 | **不管**（用户明确指示）。但由此定宽度上限 |
| AI 算错字符宽度 | **AI 自己的问题** | 构造闭合框时逐字符核对：中文/全角标点占 2 列，ASCII 占 1 列 |

**定成规则**：

- ASCII 图**整宽 ≤ 60 列**（80 列终端留 20 列余量），超了就拆图或改用不闭合形态
- 闭合框内的中英混排必须逐字符算宽度对齐右框线
- 箭头等特殊符号宽度不定，**不放在需要对齐的框内**，只用在框外连线

### D-06 · references/ 里的规则会不会没进上下文 🟢

**查证结果**（Claude Code 官方文档 `code.claude.com/docs/en/skills`）——三层加载时机是明确的：

| 内容 | 加载时机 |
|---|---|
| frontmatter 的 `description` | **常驻上下文**，AI 靠它决定要不要触发 |
| `SKILL.md` 正文 | skill 被触发时加载 |
| `references/` 下的文件 | **需要 AI 主动读取**，不自动进上下文 |

原文：「letting Claude access detailed reference material **only when needed**」「Large reference docs... **don't need to load into context every time**」。

**结论：担心是真的。`references/` 只能放「按需查阅」的材料，不能放「每次都要遵守」的规则。**

| 内容类型 | 放哪 |
|---|---|
| 每次都要遵守的规则（图在前不在后、注解是标签级、复述判据） | **必须写进 `SKILL.md` 正文** |
| 按需查阅的材料（ASCII 图样例库、题型模板库） | `references/` |

**修正原设计**：原本打算把「画板规范 + 视觉标记体系」放 `references/` 共享——**这是错的**，它们是每次都要遵守的规则。

**改法**：把这两块**压缩到最小可执行形态**（几行字），直接内联进两个 SKILL.md。重复几行的代价，远小于「规则根本没进上下文」的风险。`references/` 留给真正的查阅材料。

**官方还给了配套要求**：引用文件时必须在 SKILL.md 里说明**每个文件装什么、什么时候读**，否则 AI 不知道该不该读。另有硬指标：`SKILL.md` 控制在 500 行以内。

**顺带捞到的两个可用发现**：

1. **`paths` frontmatter 字段**——glob 模式限定 skill 只在匹配路径下自动激活。这是 T-03（沉浸模式局部作用）的候选解法，可能免掉 hook
2. **`disable-model-invocation: true`**——description 不进上下文，只有用户主动敲才加载。**正好是 `/palette` 要的**：已定「AI 只能建议、不能自动生成」，这个字段从机制上保证了它
