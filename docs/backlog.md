## P1 · 当前工作面

### T-13 · explain skill 瘦身 + 定分层硬判据 🔴

**问题一 · 重叠**：`owncc.md` 已收了画图规范、颜文字、分层结构、追问菜单格式。`explain/SKILL.md` 里还留着同样内容，两处重复必然漂移。

**处置**：skill 只保留 output style 管不了的部分——触发判断、讲解五步、复述时机、深入层流程。画图和格式全部删掉。

**问题二 · 分层交付没生效**（owncc 首测暴露）：规则说「先给最浅的一层」，但「最浅」没有可操作判据，模型无从判断，结果一口气讲完。

**建议解法（待确认）**：定成「首轮输出最多两个 `▍` 标题，给完追问菜单必须停」——可检验、不含糊。放 skill 不放 owncc，因为它只在讲解时适用，不是无条件规范。

**验证**：删完要测 skill 单独使用（用户没启用 owncc）时是否还能用。按切法 A 的约定，那种情况下格式靠模型自由发挥、流程仍完整，是可接受的降级。

### D-03 · 中等复杂度的图掉进缝里 🟢

9~15 节点原本无人接管——ASCII 画不下，`/palette` 又必须用户主动敲，结果退回纯文字。

**解法**：拆成两张分层图，或只画主干省略细节。已写进 `owncc.md` 画图段第 5 条。

### D-04 · 复述验收的触发时机 🟢

**定成两个条件同时满足才要，一次会话最多一次**：①这一轮内容有取舍、会影响后续决策 ②用户既没追问也没说出自己的理解，只回「懂了」。

依据：复述要用户打字，成本高，只在「可能假懂且后果实在」时才值。用户在追问本身就证明在思考。

---

### T-02 · 视觉标记表 🟢

放弃 emoji 方案，改用 `▍★ Insight` 块级标记 + 行内代码包裹的颜文字（八类，一律放行尾避免影响对齐）。emoji 显示宽度在终端不确定，颜文字加行内代码则同时解决了变色和宽度两个问题。

---

### D-02 · palette 的生命周期与归属 🟢

**根源**：「分全局/项目」产生时假设画板是持久存档，后来定了「按会话清空」，假设变成临时白板——旧规则没跟着改。不是需求打架，是一条过期规则。

**结论**：临时白板，固定位置 `~/.claude/atelier/palette.html`，不分全局/项目。取消这个区分，「这张图属于哪边」的判断本身就消失了。放 `~/.claude/` 而非当前目录，是为了不污染项目、不被 git 追踪。

---

### D-07 · ASCII 形态选型与宽度上限 🟢

实测两种形态（闭合框 vs 不闭合树形），**闭合框胜出**——我原本推断不闭合更稳，被实测否掉。

**关键修正**：首版规则「逐字符核对宽度」**无效**——它要求模型做机械计数，而这正是模型不可靠的地方，写进 skill 后照样算错三次。改成**框内只放 ASCII、中文注解贴框外**，模型只需数字符个数。

宽度上限 87 列（用户实测终端宽度）。禁止并排布局、禁用块状字符、宽度不定的符号不进框。

### D-06 · references/ 里的规则会不会没进上下文 🟢

官方文档确认三层加载时机：`description` 常驻上下文 ｜ `SKILL.md` 正文触发时加载 ｜ **`references/` 需 AI 主动读取，不自动进上下文**。

**结论**：`references/` 只能放按需查阅的材料，不能放每次都要遵守的规则。

**顺带发现**：`paths` 字段（限定 skill 只在匹配路径激活，是 T-03 的候选解法）、`disable-model-invocation`（description 不进上下文，只有用户敲才加载，正是 `/palette` 要的）。
