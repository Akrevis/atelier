## P0

### T-01 · MVP 划线 🔴

**问题**：设计了一大堆，但没定「第一版做到哪算能用」。全做完（日常 + 画板 + 沉浸）工期长、风险大。

**影响**：这是**元决策**——它决定其他所有条目的优先级。若 MVP 不含沉浸模式，T-03/T-05~T-10 全部降到 P3。

**建议解法（待确认）**：MVP = 日常模式两个 skill + `/palette`；沉浸模式整块留第二版。理由：日常模式每天用得上，沉浸模式要立项才启动、验证周期长。

---

### D-01 · 宽松验收与严格验收直接打架 🔴

**问题**：两条规则会同时在场，且互相矛盾——

- `explain`：核心对就行、不钻牛角尖、**不许因为用词不精确就打回**
- 沉浸模式验收：**不接受「大方向对」和解，错就是错**

**影响**：沉浸模式下学一个概念时，AI 走哪条无法确定，实际行为会随机。

**建议解法（待确认）**：**按「场景」切，不按「模式」切**——宽松是默认；严格只在用户主动喊「考我」时启用。沉浸模式下的日常讲解也走宽松。

---

### D-02 · palette 的「会话清空」与「分全局/项目」互斥 🔴

**问题**：两条已定规则逻辑上冲突——

- 按会话清空 → palette 是**临时**的
- 分全局/项目存 → palette 是**持久且有归属**的

既然每次会话都清空，分全局/项目就没意义，反正活不过这次会话。

**建议解法（待确认）**：palette 降级为**当次会话的临时画板**，生成在当前工作目录，不分全局/项目。持久化知识地图是另一个需求，现在不做。

## P1

### D-03 · 中等复杂度的图掉进缝里 🔴

**问题**：复杂度路由有个断层——

| 节点数 | 现有规则 | 结果 |
|---|---|---|
| ≤8 | ASCII | ✅ |
| **9~15** | ASCII 画不下；`/palette` 又必须用户主动敲 | ❌ **AI 只能说「建议敲 /palette」然后用文字讲**——「能画就画」落空 |
| 更复杂 | 用户敲 `/palette` | ✅ |

**建议解法（待确认）**：中间地带**拆图或画主干**——15 节点拆成两张 8 节点的分层图，或只画主干省略细节节点。符合分层交付的精神，但规则里没写。

---

### D-04 · 复述验收的触发时机没定死 🔴

**问题**：现有表述是「用户没在追问、或只说懂了 → AI **可以**要一轮复述」。「可以」不是可执行的条件。

**影响**：每次讲完都要 → 烦；从不要 → 形同虚设。不定死则实际行为随机。

**建议解法**：无。**需要一条明确的触发条件**，待设计。

---

### D-05 · explain 与 code-walkthrough 边界重叠 🔴

**问题**：真实场景会同时命中两个 skill——

- 「帮我实现一个 LRU 缓存」→ 要写代码（code-walkthrough），但 LRU 本身要讲（explain）
- 「这段代码怎么工作的」→ 不写新代码，但也不是纯概念

**建议解法（待确认）**：**有代码产出 → code-walkthrough**（内部沿用 explain 的讲解规范）；**无代码产出 → explain**。

---

### T-02 · 视觉标记表未定 🔴

**问题**：已定「用功能性视觉标记（不是卖萌）」，但具体标记表没定。

**已知边界**：终端唯一天然带色的是**代码块语法高亮**；标记必须有功能（标示内容类型），不能表达情绪。

**建议解法**：定一张小表（如 ⚠️ 坑 / 💡 关键洞察 / ❌ 反模式），数量控制在 5 个以内——多了就成噪音。

## P2

### D-06 · 跨 agent 薄壳可能导致规则没进上下文 🔴

**问题**：已定「规则写成 agent 无关的 Markdown，skill 只做薄壳」。但 Claude Code 的 skill 引用外部文件时，**AI 要多一次文件读取，且不保证它一定会读**。

**影响**：壳做得太薄 → 规则可能根本没进上下文 → skill 形同虚设。

**建议解法**：需**实测**——写一个引用外部文件的 skill，观察 AI 是否真的去读。测完再定薄到什么程度。

---

### D-07 · ASCII 中英混排对齐风险 🔴

**问题**：只验过一次（TCP 那两张图，用户判「可以」），样本量 1。

**真实风险**：中文字符宽度是英文两倍，不同终端/字体处理不一致，框线容易崩。TCP 那张图中文少，不代表通过。

**建议解法**：需**实测**——出一张中英混排密集的图（中文标签 + 英文变量名混在框线里）验对齐。

---

### T-03 · 沉浸模式激活入口 🔴

**问题**：hook 自动读 vs 用户敲命令，一直没定。

**隐含问题**：「局部作用」靠什么实现？靠目录标记文件的话，**AI 不会主动 `ls`，不知道当前目录有没有**；不用 hook 就只能每次敲命令，「局部作用」实际退化成「你记得敲命令」。

**已排除**：memkeep（语义不匹配 + 硬约束 2 禁止依赖其他包）。

**依赖**：T-01。若 MVP 不含沉浸模式，此条降 P3。

---

### T-04 · 番茄/西蒙的最终处置 🔴

**建议解法（问过两轮，未确认）**：番茄砍掉（AI 无法计时、无法主动打断，违反硬约束 3）；西蒙只留「目标拆分」，剔除「6 个月精通任意领域」这个假承诺。
