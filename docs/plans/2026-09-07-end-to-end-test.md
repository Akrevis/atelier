# 端到端实测

> Opened: 2026-09-07
> 来源：两个组件合并时发现行为判据全部未验，且这件事不能塞给任何单个开发者

## 目标

三个组件装到一起真跑一遍。**每个包各自验收合格，合起来仍然可能不能用**——这是并行开发的固有缺口，需要一个独立环节兜住。

## 边界

- **不改功能**。实测发现问题就记下来，修复另开任务
- 不做性能、不做压力，只验行为符合设计

## 推断的前提

- 假设三个组件之间无隐藏耦合——`explain` 与 `code-walkthrough` 靠 description 分流，`/palette` 靠用户主动敲，理论上互不干扰；**未验证**
- 假设插件更新后重装即可生效，不需要清缓存；**未验证**

## 完成判据

从两份已归档的 plan 里继承的三条：

- [ ] 让 AI 写一个含分支和状态的非平凡函数，它先讲思路并停下，未直接出代码
- [ ] 问一个纯概念问题，触发的是 `explain` 而非 `code-walkthrough`
- [ ] 问一个 20 节点的结构，AI 画主干并**建议**用户敲 `/palette`，而不是自行调用

本环节新增的：

- [ ] `/palette` 真跑一次，`~/.claude/atelier/projects/<项目编码>/<会话 ID>.html` 生成，浏览器打开图能看
- [ ] 同一会话敲第二次，两张图 tab 并存，第一张仍在
- [ ] 另开一个会话敲一次，落到不同文件名，**第一个会话的画板没被抹掉**（这是改存储结构要解决的问题，必须验）
- [ ] `explain` 首轮不碰五步、250 字内、停在追问菜单（瘦身后一直没验过）

## 前置

插件测试是串行的，同名插件装不了两份。开跑前确认没有别的会话正在测。
