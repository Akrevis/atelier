## 目标

MVP 三组件里唯一还没写的 skill。内容已在 `design.md` 定完，这里只是落成文件：

1. **写码前讲思路**——讲实现 / 数据流 / 边界，讲完停
2. **TDD 可配置**——TDD / 写完再测 / 混合 / 不测
3. **卡壳三档**——真不会给完整样例 + 数据流讲解；卡细节给提示或伪代码骨架；懒得想给骨架 + 失败测试 + 试过的两个方向
4. **数据流日志**——不怕冗余，收尾问要不要清理
5. **唯一硬要求**——样例给完之后关掉它自己重写一遍

同时收尾 D-05：**有代码产出 → `code-walkthrough`；无代码产出 → `explain`**。`explain` 的 description 已写入「要写代码时不触发」，需与新 skill 的 description 一起看才能最终确认不重叠、不漏触发。

| 拿不准的 | 选了 | 为什么 |

| 复述闭环要不要单独成节、要不要当开写的闸门 | 都不——只写进「讲思路」一节，且仅在「这次实现有真取舍 + 用户只回了懂了」时要一次，一次会话最多一次 | 设成闸门就是 `design.md` 第一节点名反对的验收官姿态。`glassbox-coding` 里它是硬闸门，那是个人配置，可以硬；插件面向陌生人，卡住不让写代码会直接被卸载 |
