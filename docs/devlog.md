## 2026-08-24 · 立项阶段的关键决策

### 定位从「治理解的错觉」改成「让输出可学」

**初版定位**假设 AI 要为「用户学会」负责，所以设计了强制验收、不过关不进下一步。

**用户否决**：AI 负责讲清楚，用户的理解能力不是 AI 要管的变量。复述降级为「核心对就行」的一轮校验。

**代价（已知并接受）**：取消强制复述，包就失去了唯一的反馈信号——AI 无法知道自己讲清楚没有，而「讲清楚」变成 AI 自评，恰恰是最不可靠的。

**缓解**：画板承担这个缺口。**文字讲错用户看不出，图画错很显眼**——图是把 unknown unknowns 转成 known unknowns 的转换器。这是画板在包里的真实位置，不是配图美化。

### 否决：沉浸模式独立成包

**我的建议**：日常模式（对话级、无状态）和沉浸模式（项目级、有状态、要立项）重量差一个数量级，按 AGENT-PACKS 第二道判据应该拆。

**用户决定**：整合成一个新包。

**接受，但记下代价**：沉浸模式的重量会压垮日常模式的轻便性——只想要好讲解的人被迫背上学习管理系统。

**唯一缓解**（已写进 design.md 硬约束 5）：沉浸模式不激活时必须完全不存在。抄 groundwork 的「没有标记文件就完全静默」。

### 否决：卡壳解锁三件套

**原设计**（来自 AiLearn/CLAUDE.md）：解锁要三样——代码骨架 + 失败测试或报错 + 试过的两个方向。

**用户反馈**：门槛太高、太死板。「写代码这件事不会是真不会」「你给出模板并且讲清楚原理机制数据流向，我才能更好理解」。

**判断：用户是对的，三件套的前提就是错的**。它假设「你会写、只是卡在细节」，但学新东西时的真实状态是不知道从哪下笔——这时候要求先交出骨架和两个失败方向，是不可能满足的条件。

**理论依据**：
- **样例效应（worked example effect）**：对新手，直接给完整样例+讲解比让他自己摸索更有效。摸索式学习对新手低效——认知负荷全花在「从哪开始」，没余量理解机制
- **专长逆转效应（expertise reversal）**：对新手有效的支架对熟手是累赘，反之亦然。**同一套解锁协议不可能同时适配两端**

**改成三档**（见 design.md）。唯一保留的硬要求是「样例给完自己重写一遍」——worked example 后面必须跟独立练习。

### 否决：绘制个人遗忘曲线

**原需求**：绘制个人学习遗忘曲线 + 艾宾浩斯遗忘曲线来复盘。

**关键事实**：艾宾浩斯曲线（1885）是用**无意义音节**测的——Ebbinghaus 故意剥离意义以排除背景知识污染。而实际学习的是有意义、能挂到已有知识网的材料，遗忘慢得多。**艾宾浩斯系统性高估了遗忘速度**，它的价值是定性的（遗忘先快后慢 → 复习要前密后疏），不是定量的。

**更关键**：成熟的间隔重复系统（Anki 的 SM-2、FSRS）**根本不拟合任何曲线**。它们做的是每个知识点独立跟踪，答对→间隔×系数，答错→重置。这是**反馈控制**，不是曲线预测——类比：固定重试间隔表 vs 指数退避。

**为什么反馈控制更好**：拟合曲线要大量数据且假设参数稳定；反馈控制只需要「上次答对没有」一个信号，简单且鲁棒。

**结论**：不画曲线。只维护每个知识点的「下次复习时间」。艾宾浩斯唯一作用是给初始间隔一个起点。实现难度从「统计拟合」降到「一个 JSON 字段 + 乘法」。

### 事实纠正：西蒙学习法

「6个月精通任意领域」不是 Herbert Simon 的观点，是中文互联网的营销化改写。Simon 本人的结论相反——专业能力约需 10 年/数万小时（这是「一万小时定律」的源头）。

**为什么必须纠正**：这个假承诺会直接毒化时间预算模块，让 AI 按一个假基准估工期。

可用的内核只有「确定目标 → 拆分目标」。

### 事实核查：CLAUDE.md 并没有禁 emoji

用户认为输出枯燥是因为「我在 CLAUDE.md 里说了不能用表情符号」。

**实际查证**：全局 CLAUDE.md 搜 `emoji|表情|符号|图标` 零匹配。相反它明确写着「**严格是对内容的，不是对语气的**——该松就松，可以调侃、可以吐槽、可以有个人色彩」。

**结论**：枯燥是 AI 执行时把「内容严格」过度延伸到语气，是执行偏差，不是配置问题。

**但更重要的**：学习场景下，视觉标记不是审美问题是**功能问题**——情绪唤醒增强记忆编码，视觉区分度降低扫读成本。可做的是一套功能性标记（⚠️ 坑 / 💡 关键洞察 / ❌ 反模式），不是卖萌。终端唯一天然带色的是代码块语法高亮。

### 画板：动机被我理解偏过一次

**我的初版定位**：图能表达文字表达不了的结构，目标是**准确**。

**用户真实动机**：输出全是文字，专注力/注意力/理解力有限，要**快**。目标是**省力**。

**推出的三条硬约束**（已写进 design.md）：
1. 图要**替代**文字不是补充——画了图还配三段解释＝总量更大
2. **当场可见 > 图漂亮**——切窗口是注意力断点，对「注意力有限」这个前提是最贵的成本
3. 图必须**小**——30 节点的图和 500 字文字认知负荷差不多

**意外收获**：省注意力的方案恰好就是省 token 的方案，两个目标同向，不用取舍。

### 实测：三种画法对比

同一内容（TCP 三次握手）出三版：ASCII 时序图 / ASCII 状态机 / Artifact 渲染 Mermaid。

**用户判定**：ASCII 可以，但**需要注解说明**。

**由此定的约束**：注解必须是**标签级**（贴在箭头/节点旁），不允许图画完在下面另起一大段复述——那样就是我警告过的负优化。

**裸 Mermaid 判死**：Claude Code 终端不渲染，直接吐代码块用户看到的是 `graph TD; A-->B` 源码，比纯文字更难读。

### 大纲：从「无解」改成「需要锚」

**我的初判**：AI 是响应式的，补不回书的大纲；让 AI 生成大纲它会按训练数据里最常见的教程结构拼，而你正在学的东西恰恰是你最没能力验证的。

**用户纠正**：`AI方向实习求职路线.md` 就是 AI 基于网络搜索 + 真实 JD 分析出来的。

**修正后的边界**：AI 可以做大纲，但必须**锚在外部可验证材料上**（JD、官方文档目录、标准、真实课程结构），不许凭训练记忆直吐。这和 groundwork 治幻觉是同一套逻辑——不是不让它说，是让它说的话有出处。
